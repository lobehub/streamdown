# AGENTS.md

Guidance for coding agents working **in** this repository. Downstream users of the package should
read <https://streamdown.lobehub.com/skills.md> and <https://streamdown.lobehub.com/llms.txt> instead.

## Overview

`@lobehub/streamdown` is an ESM-only, headless React 19 component that renders streaming markdown:
block splitting and caching, smooth per-character reveal, a fade animation and a LaTeX guard, built
on `react-markdown`, `marked` and `remend`. It has two entries, `@lobehub/streamdown` and
`@lobehub/streamdown/profiler`. The docs site (<https://streamdown.lobehub.com>) is built with
`@lobehub/docs-kit` (the `lobedocs` CLI) from `docs/` and the `index.mdx` files under `src/`.
Single pnpm package, Node >= 22.22 for the docs site.

| Path                                                        | What lives there                                                                      |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `src/index.ts`                                              | Main entry; every public export is listed here                                        |
| `src/Streamdown.tsx`                                        | The component and `StreamdownProps`; wires lexer, queue, smoother and rehype plugins  |

| `src/rehypeStreamAnimated.ts`, `src/streamAnimationMeta.ts` | Rehype plugin that wraps newly revealed text, and per-block animation timing          |

| `src/CachedMarkdown.tsx`, `src/StreamTail.tsx`              | Memoized per-block renderer; streaming tail element                                   |

## Using Skills

Skills follow the `.agents/skills/<name>/SKILL.md` convention: read the whole `SKILL.md` (and any
`reference/` files it links) before starting a task it covers, then follow it.

Skills committed in [`.agents/skills/`](./.agents/skills) (copies of the docs-kit skills, also
kept in [lobehub/lobe-ui](https://github.com/lobehub/lobe-ui/tree/master/.agents/skills)):

| Skill                   | Use it when                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| `using-docs-kit`        | Writing or fixing `index.mdx` pages, demos, `<Api>` tables, `docs.config.ts`, or a failing build |
| `building-landing-home` | Changing the landing page in `docs/home/` built from `@lobehub/ui/awesome`                       |

When you add a skill, put it under `.agents/skills/<name>/` and list it here. The site's
`skills.md` and `llms.txt` are generated by `lobedocs build` for downstream users; never edit them
by hand.

## Writing Docs

- **Component pages**: only files named `index.mdx` under `src` (`atomDirs`) become pages; the URL
  comes from the folder: `src/Streamdown/index.mdx` → `/components/streamdown`,
  `src/profiler/index.mdx` → `/components/profiler`.
- **Guide pages**: `docs/guide/<name>.mdx` with `title` + `description`, listed in `publicDocs` and
  `themeConfig.navItems` in `docs.config.ts`. They are served at `/guide/<name>`.
- **Frontmatter**: `title`, `description` (one or two plain sentences; feeds search and llms.txt),
  `category` on component pages (`General`), optional `order`. A PascalCase `title` makes the page
  header show `import { Title } from '@lobehub/streamdown'`, which is why the profiler page is
  titled `Streamdown Profiler`.
- **Demos**: must live under `src/**/demos/`. One default export per file, import the library by
  package name (`@lobehub/streamdown`, `@lobehub/streamdown/profiler`; `docs.config.ts` aliases them
  to `src`). Shared demo helpers (simulated stream, samples, `StreamPane`, `ProfilerPanel`) are in
  `src/Streamdown/demos/shared/`. Guide pages import demos with a relative path, e.g.
  `import Latex from '../../src/Streamdown/demos/Latex.tsx?demo';`. Demos that import local helpers
  need `editable={false}`; the playground uses `StoryBook` + `useControls` from
  `@lobehub/ui/storybook` with `layout="bare"`.
- **API tables**: `<Api name="Streamdown" />` and `<Api name="StreamdownProfilerProvider" />` read
  props from TypeScript. JSDoc on props becomes the description, and a JSDoc `@default` must equal
  the runtime default in the destructuring or the build fails.
- **Links**: use site pathnames (`/guide/latex`, `/components/streamdown#api`); the build audits
  every internal link and `#hash`.
- **Preview and check**: `pnpm dev`, then `pnpm build:site`, which runs every docs audit. Restart
  the dev server after editing `docs.config.ts`.

## Adding to the Library

- **New prop**: add it to `StreamdownProps` in `src/Streamdown.tsx` with JSDoc, destructure it with
  its default in `Streamdown`, and thread it to where it is used (`StreamdownBlocks`, the smoother or
  the lexer). Props that are not destructured flow into react-markdown `Options`. Add a test to
  `src/Streamdown.test.tsx`, then document it in `src/Streamdown/index.mdx` (and the README's
  Common Options table if it is commonly used).
- **remark / rehype plugins**: user plugins arrive through `remarkPlugins` / `rehypePlugins`.
  Built-in per-block plugins are appended in `resolveBlockPlugins` in `src/Streamdown.tsx`
  (that is how `rehypeStreamAnimated` is added). Put a new plugin in its own `src/<name>.ts` with a
  colocated `src/<name>.test.ts`, and export it from `src/index.ts` if users should compose it.
- **Animation**: the fade CSS lives in `src/styles.tsx`; which nodes animate and when lives in
  `src/rehypeStreamAnimated.ts` (wrapping) and `src/streamAnimationMeta.ts` (timing). Keep the
  `prefers-reduced-motion` rule working.
- **Block processing**: splitting and freezing are in `src/blockLexer.ts` (`FROZEN_TYPES`), block
  states in `src/useStreamQueue.ts`, pacing presets in `src/useSmoothStreamContent.ts`. Lexer
  changes must keep `src/blockLexer.test.ts` green: it compares incremental lexing to a full lex at
  every step of the docs samples in `src/Streamdown/demos/shared/samples.ts`.
- **Profiler metrics**: `src/profiler/profiler.ts`; export new public types from
  `src/profiler/index.ts`.
- **Tests**: colocated `src/**/*.test.{ts,tsx}` (vitest, jsdom, globals). Vitest aliases
  `@lobehub/streamdown` to `src`.
- **Exports**: public API goes through `src/index.ts` or `src/profiler/index.ts`. Both are the
  `tsdown` entries (`tsdown.config.ts`) and the `exports` in `package.json`. A new subpath entry
  needs a `tsdown` entry, a `package.json` export and the alias regex in `vitest.config.ts`
  (which only maps the root and `/profiler`). Runtime dependencies are externalized from
  `dependencies` / `peerDependencies`, so add new ones there.

## Commands

```bash
pnpm install          # also runs husky and `lobedocs typegen` (prepare)
pnpm dev              # docs dev server (lobedocs dev)
pnpm lint             # eslint on src/, docs/ and docs.config.ts
pnpm type-check       # tsc (library, demos and docs)
pnpm test             # vitest run; `pnpm test:coverage` is what CI runs
pnpm build            # tsdown → es/
pnpm build:site       # lobedocs build → dist/ (with all docs audits)
pnpm deploy:site      # build:site + wrangler pages deploy; maintainers only
```

CI (`.github/workflows/test.yml`) runs lint, type-check, test:coverage, build and build:site.

## Commits and Releases

- Commit messages are gitmoji + conventional commit, enforced by commitlint in the `commit-msg`
  hook: `✨ feat: ...`, `🐛 fix: ...`, `⚡️ perf: ...`, `📝 docs: ...`, `🔧 chore: ...`,
  `✅ test: ...`, `♻️ refactor: ...`. Never use `--no-verify`.
- Every push to `main` runs semantic-release (`.github/workflows/release.yml`), which publishes to
  npm. `feat` releases a minor, `fix` and `perf` release a patch, and a breaking change a major.
  Use those types only for changes to the published library in `src/` (excluding docs and demos);
  docs, demos, CI and tooling changes use `docs`, `chore`, `ci`, `test` or `refactor`.
- Never bump the version or edit `CHANGELOG.md` by hand; the release job does it.
